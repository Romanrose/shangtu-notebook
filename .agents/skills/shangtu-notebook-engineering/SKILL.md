# 手札目标驱动工程

使用本 Skill，将“时空探索手札”保持为一本会回应的手写书，而不是聊天产品或图谱浏览器。它把 Karpathy 风格的四项原则——先思考、保持简单、手术式改动、目标驱动验证——落实为本项目可执行的工作流。

本 Skill 偏向谨慎而非速度；明显且低风险的微小改动可以简化流程，但绝不跳过产品不变量。

## 何时使用

用于本仓库内所有非简单的产品、前端、Pi 工具、CNKGraph、视觉转写、状态管理、测试和华为平板验收工作。纯拼写修正或不影响行为的一行改动，可直接遵守根目录 `AGENTS.md` 的最小改动原则。

## 开始前的最小阅读集

1. 完整阅读根目录 `AGENTS.md` 与 `docs/mvp-contract.md`。
2. 阅读最小受影响的代码、样式、测试或文档面。
3. 涉及 Pi、模型、凭据或服务端时，阅读 `docs/pi-tool-contract.md`。
4. 涉及寻迹回应、旁批或状态分支时，阅读 [三分支验收矩阵](references/acceptance-matrix.md)。

不要向用户询问仓库或上述文档已经给出的事实。

## 工作协议

编辑前先用以下格式声明，保持简短具体：

```text
Goal: <可观察、可验证的结果>
Constraints: <本任务适用的边界>
Smallest change: <最小实现路径>
Not changing: <刻意不碰的邻近范围>
Acceptance checks: <命令、断言或真机操作>
```

然后按“最小步骤 → 最窄验证”循环执行。每个改动都必须能追溯到 `Goal`、用户请求或项目不变量。

出现下列任一选择时暂停并请求用户决策：它会实质改变纸页交互、事实/联想边界、Pi 工具权限、数据来源、隐私/凭据边界或交付范围。不要暗中替用户选择。

## 不变量检查清单

### 纸页与笔迹

- 纸页是唯一主界面；不得在演示路径加入聊天面板、默认图谱面板、常规文本输入或可见技术控制。
- 原笔迹永远保留；转写是可编辑派生版本，绝不覆盖原笔迹。
- 寻迹模式在停笔一秒内，必须先显示完全本地的“识字中”与纸页苏醒状态；网络和模型不得阻塞它。
- 静读模式只保留笔迹，不得调用 Pi。

### 证据与回应

- 证据旁批只可陈述带来源的可核验事实，并保留可展开的来源和有界路径。
- `联想` 必须显式标注，且在视觉与语义上不与证据混淆。
- 歧义转写或实体必须呈现候选或可编辑文本，禁止静默选择。
- 无证据时呈现证据缺口，禁止伪造来源、时间、人物关系或记录。

### Pi 与数据

- Pi 只能使用合同允许的受控工具；不能获得环境文件、任意网络、自动发现的工具或项目上下文。
- 浏览器不接触 Pi、模型或 CNKGraph 凭据；服务端承担受控调用。
- 旧项目 `/home/romanrose/Project/shangtu` 只读，且仅可复用已验证的查询/来源追溯能力，不能迁移旧前端。

## 保持简单与改动边界

- 不添加未被验收标准要求的特性、依赖、抽象、配置或容错分支。
- 不为只使用一次的逻辑建立通用框架；若实现明显超过目标所需，先简化。
- 不重构、不格式化、不清理无关代码；发现既有问题只报告。
- 只清理由本次变更造成的未使用代码或失效导入。
- 优先交付真实纵切面，之后才讨论泛化、打磨或扩展功能。

## 验收路径

对影响寻迹行为的改动，必须覆盖：

| 分支 | 可见证明 | 禁止事项 |
| --- | --- | --- |
| 有证据 | 原笔迹保留；证据旁批可打开含来源和有界路径的寻迹卡 | 把模型联想混入证据旁批 |
| 有歧义 | 页边澄清给出候选或可编辑转写 | 静默选定实体 |
| 有缺口 | 页边明确证据缺口；可选补充标为“联想” | 虚构来源、日期、关系或记录 |

所有三分支还须确认：寻迹模式停笔一秒内出现本地苏醒，静读模式不调用 Pi。

根据改动范围运行最窄检查；若依赖已经安装，完成前运行受影响的下列命令：

```bash
npm run check
npm run build
npm run check:agent
```

涉及交互时，记录具体华为平板验收：横竖屏各测试一次；触控笔与手指各书写一次；确认书写、停笔反馈和滚动不抢手势。

## 交付格式

报告：

- 改动文件与原因；
- 实际运行的命令及结果；
- 覆盖的验收用例；
- 假设、已知缺口和明确延期项。

只报告实际验证过的结果；依赖、凭据或真机不可用时，应如实说明。
