# 一笔入史：时空探索手札

## 目标

让公众先在平板纸页上写下一个想追寻的人物，再沿着可追溯的“人物—时间—地点—事件—作品”路径一笔一笔获得回应。比赛演示以苏轼为主角，但产品入口不把人物固定为苏轼；纸页是唯一主界面，系统不以聊天窗口或默认图谱取代书写。

首版可观察结果：用户停笔后先在一秒内看到本地“识字中”，随后纸页以另一种批注笔迹逐字写出已核验的回应，并可打开来源与有界路径。

## 范围与非目标

当前实现以已确认人物作为叙事锚点：受控搜韵 gateway 提供人物档案、作品候选与“人物—作品—路线词”的有限检索，但不宣称覆盖全人物、全朝代图谱，也不进行历史推演。离线夹具仍用于无网络排练；真实服务只有在服务端完成 gateway、Pi 与可选 OCR 配置并通过预检后才启用。

模型只能提出澄清、检索或旁批建议。事实正文、时间、地点和关系必须由服务端已验证的图谱边与来源生成；文化性补充必须显示“联想：”。

## 书页状态

```text
静读 → 书写 → 停笔反馈 → 转写确认 → 寻迹 → 纸页回应 → 寻迹卡 → 收为印
```

- 静读：只保存笔迹。
- 停笔反馈：完全由前端触发，不等待 OCR、模型或图谱。
- 转写确认：机器转写可编辑；低置信度或实体不唯一时给出候选。
- 纸页回应：在原笔迹下方逐字显现；证据的完整来源与路径在点按后展开。

## 模块边界

```text
src/
  main.tsx                     纸页编排、手写与页面状态
  demo-agent.ts                无网络的三分支演示结果
  modules/paper-reply/         纸页回应文本与显字节奏
  notebook-store.ts            IndexedDB 原始笔迹与页面保存

server/
  notebook-server.mjs          /api/transcribe、/api/seek、/api/narrative 边界
  transcription-adapter.mjs    受控 OCR 适配
  journey-agent.mjs            人物锚点、路线归一化、作品候选与联想编排
  run-seek.mjs                 Pi 会话与受限寻迹编排
  seek-outcome.mjs             路径、来源与旁批核验
  cnkgraph-gateway.mjs         notebook 对 gateway 的认证、有界查询与响应校验
  souyun-gateway-service.mjs   /anchor、/works、/seek 到搜韵 API 的转换
  cnkgraph-fixture.mjs         可替换的离线证据夹具
```

开发期由 `vite.config.ts` 把三个 `/api/*` 路径装载到 `notebook-server.mjs`；独立部署时才启动 `npm run serve:api`。浏览器只提交当前笔迹片段 PNG 与用户确认的短文本；OCR、Pi 与图谱凭据只存在于服务端。Pi 工具面固定为实体澄清、图谱检索、证据核验和旁批生成。完整启动与调用顺序见 [操作与架构指南](operation-guide.md)。

```ts
type InkSegment = {

type HistoricalEvidence = {
  subject: string;
  relation: string;
  object: string;
  source: { id: string; label: string; url: string; claim: string };

```

前端展示的寻迹结果只有四种：`evidence`、`ambiguous`、`gap`、`association`。任何来源或路径不匹配的证据提案都降级为 `gap`。

## 迭代顺序

1. 纸页回应：实现纸张上逐字显现的第二套批注笔迹。
2. 苏轼离线演示：固定“苏轼—《前赤壁赋》—赤壁”证据路径与来源。
3. 转写确认：保留原笔迹、允许修订机器转写，并显示实体候选。
4. 人物锚点：首屏提示“起笔：写下一个你想追寻的人物”，先确认人物，纸页边留下受限人物档案来源与一条标注为“档案摘录”的原文片段，再选择地点、经历或作品路线（也可直接按提示手写），把下一笔收敛到一条可控路径。每个片段采用“定位 → 据（可核验事实） → 连接（时间/地点/路径） → 邀请继续”四拍，路线内部按“起点—转折—回望—收束”推进；路线卡还显示“线索提示”，给出当前节拍适合填写的具体线索类别，地点首笔可从受限人物档案的籍贯开始。第四条证据后允许收纳或继续写新的回声。摘录来自搜韵人物档案，不由 LLM 编写生平。
5. 真实路线检索：在受控服务端调用搜韵 `Writing/Find`，快速返回来源支持的“人物—作品—记有路线词”路径，并保留命中原文中的时间词；相同人物/路线/线索的成功路径使用有界缓存，明确的证据缺口短暂负缓存以避免重复等待上游，前两条路径先由本地即时联想承接，之后再异步调用受限叙事层生成“联想”，不阻塞证据和下一笔。证据缺口只提示补充线索，不推进“起点—转折—回望—收束”的步数。
6. 旅程串联：在当前纸页边栏保存最近六条有界路径，并仅显示已核验的时间/地点线索，形成可回看的短路线与线索串；点击“续页”时继承当前人物旅程，点“换人物”后再写下新人物名即可切换锚点，避免把“赤壁”“黄州”等短地点误判成姓名。
7. 二级时空视图：仅从寻迹卡按需展开完整时间线或地图，不成为主界面。

纸页管理：底部“清空”是当前页级别的可确认重置，不删除其他页；它同时取消当前请求，保证旧响应不会在清空后重新落纸。

旅程状态以人物为中心保存，而不是把每次寻迹当成孤立问答：

```ts
type JourneyState = {
  personId: string;
  route: "life" | "space" | "work" | null;
  currentBeat: number;
  visitedNodes: string[];
  unresolvedQuestions: string[];
};
```

旧页面只保存了人物锚点和路径历史时，打开页面会由历史路径迁移出 `visitedNodes`，并把当前 `nextPrompt` 作为唯一的 `unresolvedQuestions`；原始笔迹和证据旁批不被迁移逻辑覆盖。

## 验收

- 原始笔迹、逐字回应、来源卡和印章在翻页后仍保留。
- 寻迹模式停笔一秒内出现本地反馈；静读模式不发起寻迹。
- 有证据、实体歧义、证据缺口三分支均有可见证明。
- 华为平板横竖屏各测试一次，触控笔和手指各书写一次，确认纸页不被浏览器滚动抢占。
