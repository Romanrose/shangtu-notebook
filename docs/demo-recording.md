# 三分钟验收与录屏脚本

此文件服务于当前没有模型/API 凭据时的稳定排练。URL 参数只选择**离线演示夹具**，不是正式寻迹逻辑；正式版本会由视觉转写 + Pi 白名单工具替换。

比赛现场若需要不依赖外部 OCR，可运行 `NOTEBOOK_FIXTURE_MODE=1 npm run dev -- --host 0.0.0.0`；页面会保留“演练转写（未调用视觉模型）”标记，不能将该入口记录为真实识别准确率。

改动后先运行 `npm run check`、`npm run check:agent` 和 `npm run check:journey-agent`。它们覆盖转写、证据、歧义、缺口、人物锚点和叙事隔离的服务端合同；仍不替代真实平板手写验收。

当前纸面交互中，机器转写会锚定在本次笔迹附近，以可编辑的手写层显示；确认按钮和候选项仍嵌在该纸面层内，不跳出独立对话框。
如果视觉服务超时或没有读出文字，纸页会保留空的可编辑确认框；用户可以直接补写，也可以点击“再识别一次”，两者都不会丢失原始笔迹。
完整启动顺序、真实 gateway 探针与 PWA 操作见 [操作与架构指南](operation-guide.md)。

1. 打开 `/?demo=evidence`：写“苏轼与赤壁有什么关联？”；停笔后应先在 1 秒内出现“识字中”，随后出现证据旁批、`联想` 旁批和印章。点按证据旁批，确认寻迹卡中有来源和 `苏轼 → 于1082年作 → 前赤壁赋 → 记有 → 赤壁`。
2. 打开 `/?demo=ambiguous`：写“苏辙和黄州有什么关联？”；停笔后确认只出现澄清旁批与两个候选，不会擅自选人。点“苏轼”后进入固定来源证据，点“苏辙”后进入明确证据缺口。
3. 打开 `/?demo=gap`：写“苏轼与未署名古画有什么关联？”；停笔后确认出现证据缺口，补充内容明确标作 `联想`，没有伪造来源。
4. 切到“静读”写一笔：应只留下笔迹，不出现“识字中”或旁批。
5. 在 evidence 页点“收为印”：关系纹路淡去，仅留下页边印；再点印章应还原旁批和寻迹卡入口。
6. 打开 `/?demo=journey`：首笔建立固定的“苏轼”人物锚点；点击地点、经历或作品路线，再写一笔，确认纸页按“定位—据—连接—继续写”四拍显示路线标签、起点—转折—回望—收束提示、时间词和来源卡；第四条证据后点击“收纳这条路线”，确认旁批变为印章且仍可点印恢复。真实服务入口中，路线未定时也可直接写下“地点线 / 经历线 / 作品线”完成选择。该入口是固定演练，不代表真实服务结果。

平板验收：在华为平板浏览器打开 PWA，横竖屏各写一次；确认触控笔与手指均可画、浏览器滚动不抢手势、停笔立即出现本地苏醒状态。

## 受控真实服务补充

在服务端完成 `npm run preflight:services` 与 `npm run preflight:souyun-gateway` 后，先写并确认“白居易”或其他受支持人物，纸页应先出现人物锚点与三个路线印记；例如点“作品”后写“代表作”，再选择《招王质夫》，应出现带来源的“白居易 → 作者 → 招王质夫”路径与时间线。也可演练唯一别名归一；若别名对应多个作者，应先点“换人物”，再写新名字并在多候选时确认，不能静默替换人物。随后可能异步出现一条单独标注为“联想”的文化补充；即使联想服务超时，证据旁批和下一步提示仍保留。
